# Agent Note：基于完整日志的用量面板

状态：已实现

[English](2026-08-14-whole-log-usage-dashboard.md) | 中文

## 问题

Web 客户端已经会在当前会话底部显示精简统计，但没有跨会话的本地总览。若直接统计已渲染的聊天节点，会漏掉未加载分页、被压缩的历史以及未挂载会话。另建分析数据库或遥测链路又会重复现有追加式会话日志，并产生不必要的隐私边界。

## 决策

由 `@deepseek-ai/dsh-session-stats` 维护完整日志的 `usageStats` 投影，聚合每日供应商用量、工具与 Skill 调用、当前请求头元数据和步骤开始事件。同一步骤若收到多次供应商用量报告，以最新样本替换旧样本。模型与推理强度计数发生在 `step/start`，因为 `request/header` 表示一次配置纪元或变化，并不是每个请求都会重复出现的事件。

Host 已维护的投影基线随会话列表行一并返回。仅用于 Web 的 `@deepseek-ai/dsh-client-ui-usage` 插件在设置页对应分区挂载后才请求 `session.list`，在浏览器中合并各会话基线，并在页面保持打开时每分钟刷新一次。它通过声明式设置槽加入界面，向渲染器注入 `SnapshotStore` hook，而不在业务插件中导入 Web 渲染器 hook。

整条链路只在本机运行，不会把用量、会话、凭据、工作区路径、壁纸状态或其他 Harness 配置发送到外部分析服务。

## 考虑过的替代方案

- 不采用统计已加载聊天节点，因为分页、压缩和未挂载会话会造成结果不完整。
- 不采用独立分析数据库或遥测服务，因为会话日志已经是事实来源，额外存储会带来同步与隐私风险。
- 不新增全局用量 RPC，因为会话列表的投影传递已经提供有界且可检查点化的摘要。
- 不把 `request/header` 计作请求，因为模型或推理强度不变时该事件不会在每一步重复，统计会偏低。

## 后果

- 会话列表的投影行会稍微变大，但仍是有界摘要，不包含原始事件历史。
- 冷会话检查点可能暂时落后于日志尾部，直到该会话再次挂载并写入检查点；`asOfSeq` 会保留这一新鲜度边界。
- 每日分桶使用日志回放时的 Host 时区；若在不同时区的 Host 回放，午夜附近的事件可能落入不同日期。
- 面板只报告 token 与调用次数，不推断货币成本。
- 设置页面打开时每分钟进行一次本地刷新，并在卸载时释放监听器、定时器和 Store 更新。
